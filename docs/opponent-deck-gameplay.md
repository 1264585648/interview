# 对手匹配与题目卡组玩法规划

状态：已确认的产品方向，等待后续迭代实现。

## 一句话定义

首页匹配的不是题目分类或挑战模式，而是一个真正的面试对手。匹配成功后，对手携带自己的题目卡组登场，玩家通过连续抽题、回答和追问完成一场三轮面试对局。

```text
面试大厅
→ 转轮搜索对手
→ 锁定并揭晓对手
→ 对手题目卡组登场
→ 从五张卡中完成三轮抽题
→ 回答与对手追问
→ 对局结算与复习牌库
```

## 核心对象

### 对手

对手是首页转轮的唯一匹配对象。每个对手包含：

- 独立名称、徽章和登场表现；
- 面试风格与难度范围；
- 一个会改变回答要求的被动能力；
- 擅长的题目领域；
- 一套按规则动态生成的题目卡组；
- 特有的追问方式。

### 对手题目卡组

对手题目卡组属于本局对手，不等同于玩家的错题或收藏牌库。匹配成功后，它以五张卡背组成的扇形卡组登场，玩家不会提前看到完整题目，只能看到领域符号、难度和卡牌位置。

### 玩家复习牌库

玩家答得不完整、被追问击穿或主动标记的题目，在结算后进入复习牌库。它用于长期复习，不参与首页匹配。

## 首页：只匹配对手

现有轮盘中的挑战模式槽位将全部替换为对手。限时、追问、复盘等规则不再作为首页槽位，而是由对手被动、每日规则或独立入口承载。

第一批建议提供八个对手：

| 对手 | 定位 | 被动能力 | 主要卡组 |
| --- | --- | --- | --- |
| 旗鼓相当的对手 | 自适应陪练 | 根据玩家近期表现调整题目难度 | 薄弱主题与同等级综合题 |
| 赛博面试官 | 标准 AI 面试官 | 回答缺少结构时缩短下一轮思考时间 | Agent 工程综合题 |
| 系统架构师 | 架构专家 | 没有容量、边界或取舍时发动追问 | Planning、Runtime、架构设计 |
| 故障猎手 | 稳定性专家 | 没有监控、降级或恢复方案时发动追问 | Observability、Tracing、故障定位 |
| 记忆守门人 | Memory 专家 | 制造来源、时效或上下文冲突 | Memory、Context、Provenance |
| 工具调度官 | Tool Calling 专家 | 强制检查权限、幂等、超时和失败边界 | Tool Use、Workflow、Side Effects |
| 产品质疑者 | 业务型面试官 | 追问价值、成本、必要性和用户体验 | 产品判断与工程权衡 |
| 终局主考官 | Boss 对手 | 混合题组并连续发动递进追问 | 全主题高难度综合题 |

## 一局卡组

每局先生成五张题目卡，再从中完成三轮。

```text
[开场题] [基础题] [深入题] [压力题] [终局题]
                ↓ 本局抽取三张
        开场轮 → 深入轮 → 压力轮
```

卡组生成建议比例：

- 40% 对手专长题；
- 30% 玩家近期薄弱题；
- 20% 与玩家等级相符的综合题；
- 10% 随机事件题。

生成约束：

- 同一局不出现重复题；
- 第一题必须能建立上下文，不直接使用最高难度；
- 第二题优先深入第一题涉及的工程决策；
- 第三题加入故障、限制条件或需求变化；
- 题目在匹配开始时确定，动画只负责表现，不能在落点后篡改结果；
- 题库数量不足时降低卡组数量，但不能伪造不存在的题目。

## 三轮面试流程

### 第一轮：开场

- 抽取概念或基础设计题；
- 玩家获得较完整的思考时间；
- 用于判断是否掌握主题边界和基本结构。

### 第二轮：深入

- 抽取实现、架构或方案权衡题；
- 对手根据上一轮遗漏决定是否追加追问；
- 重点检查可落地性，而不是只复述概念。

### 第三轮：压力

- 加入时间限制、系统故障、需求变化或上下文冲突；
- 对手被动能力在这一轮完整生效；
- 用于判断玩家能否在限制条件下修正方案。

单轮状态：

```text
抽取题目
→ 整理思路
→ 文字或语音回答
→ 评分关键维度
→ 对手追问或通过
→ 记录本轮结果
```

## 对局数值

避免直接使用传统生命值，采用更符合面试语义的两个指标：

- 玩家镇定值：连续遗漏关键点或追问失败时降低；
- 面试官认可度：回答正确、结构完整并说明工程取舍时提高。

三轮结束后，认可度达到目标即挑战成功。镇定值归零不删除学习进度，相关题目进入复习牌库。

建议评分维度：

| 维度 | 权重 |
| --- | ---: |
| 技术正确性 | 35% |
| 结构清晰度 | 20% |
| 方案权衡 | 15% |
| 工程案例 | 15% |
| 回答相关性 | 10% |
| 时间控制 | 5% |

## 旗鼓相当的对手

旗鼓相当的对手不是固定难度人物，而是默认的自适应快速匹配入口。它读取：

- 各主题熟练度；
- 历史回答评分；
- 最近错题；
- 平均回答时间；
- 已击败对手。

随后生成与玩家能力接近、略高于舒适区的卡组。目标不是让玩家稳定获胜，而是让每局都能暴露一到两个值得复习的薄弱点。

## 页面表现

### 匹配前

- 顶部为未知对手席；
- 中央转轮包含八名对手的徽章与名字；
- 底部只显示玩家信息和开始匹配操作。

### 对手揭晓

- 目标对手从转轮进入顶部对手席；
- 展示名称、称号、被动能力和推荐难度；
- 转轮退入后景，不立即弹出单道题。

### 卡组登场

- 对手的五张题目卡背从对手席或牌库位置落入牌桌；
- 卡组以扇形展开，显示领域符号和难度曲线；
- 玩家选择“接受挑战”后抽取第一张题。

### 对局中

- 顶部：对手、被动能力与认可度；
- 中央：当前题目卡和追问；
- 底部：玩家镇定值、回答区和剩余题目牌库；
- 已完成卡牌进入侧边战绩区，不遮挡当前题目。

## 状态机建议

```text
lobby
→ matching
→ opponent_locking
→ opponent_reveal
→ deck_summon
→ deck_ready
→ round_draw
→ answering
→ counter_question
→ round_result
→ battle_result
```

页面状态应由单一 reducer 或状态机管理。题目抽取、动画表现、回答评分和结算数据彼此分离，避免在动画组件内部修改业务结果。

## MVP 边界

第一版只实现完整的一局，不立即加入玩家策略卡构筑：

1. 首页八个槽位全部替换为对手；
2. 匹配并展示一名对手；
3. 根据对手规则生成五张题目卡；
4. 卡组以卡背形式展开；
5. 自动抽取三张，完成三轮题目展示；
6. 使用本地模拟评分完成流程；
7. 展示对局结算和复习牌库入口。

后续版本再加入真实文字/语音回答、AI 评分、动态追问、玩家策略卡和爬塔模式。

## MVP 验收标准

- 首页轮盘只出现对手，不出现题目分类或挑战模式；
- 八名对手拥有不同名称、专长、被动和卡组规则；
- 匹配结果与最终进入对手席的角色一致；
- 对手揭晓后先展示卡组，再抽取题目；
- 卡组至少能表达五张卡与三轮难度曲线；
- 一局不会重复抽到同一道题；
- 三轮完成后进入统一结算，而不是直接跳回匹配页；
- 题目卡可以进入真实题目详情；
- 320px、768px、1440px 无横向溢出；
- 键盘、状态播报和减少动效模式可完整走通一局；
- `npm run build` 通过，浏览器控制台无运行错误。
