# 符文试炼匹配轮：设计计划

## 设计命题

- 主题：面向 AI Agent 工程师的原创“符文试炼匹配轮”。
- 受众：正在准备 Agent Runtime、Memory 与系统设计面试的工程师。
- 页面唯一任务：先匹配一位面试对手或一种挑战模式，再从独立题库发出一道题，并让用户直接进入对应题目开始作答。
- 隐喻：轮盘不是题目选择器或赌场转轮，而是一台把不同面试情境编排为执行轨迹的“运行时仪表”；真实题目始终保存在独立牌库中。

## 颜色 token

页面沿用站点现有 token，不引入孤立的原始颜色值：

| 角色 | Token | 值 | 用途 |
| --- | --- | --- | --- |
| 石灰底 | `--canvas` | `#F3F5F2` | 页面背景与留白 |
| 骨白面 | `--surface` | `#FFFFFF` | 题卡与控制台表面 |
| 石墨墨 | `--text` | `#202421` | 标题、关键读数 |
| 矿物绿 | `--accent` | `#315E50` | 主动作、锁定轨迹 |
| 雾银线 | `--line` | `#D7DDD8` | 仪表刻度、结构分隔 |
| 黄铜火 | `--warning` | `#8A651D` | 指针、命中火花与难度标记 |

## 字体角色

- 显示字体：`--font-display`，用于页面标题和揭晓题目；字重克制，靠紧凑字距形成“铭牌”感。
- 正文字体：`--font-body`，用于说明、题目摘要和按钮，保证中文长句可读性。
- 工具字体：`--font-mono`，用于状态、槽位、难度和运行读数，表达 Agent Runtime 的工程语境。

## 唯一 signature

“执行轨迹环”：八枚窄铭牌不是题目，而是四位面试对手与四种挑战模式；它们作为八个可调度节点围绕中心 Agent Core 排列，内圈用 SVG 画出断续 Trace/Checkpoint 路径。指针先锁定面试情境，随后下方独立牌库才发出真实题目。

## 动效与状态

`idle → searching → locking → reveal(match result) → dealing → ready(question card)`

- `idle`：执行轨迹轻微呼吸，主按钮可用。
- `searching`：轮盘匀速巡检，状态区明确显示“正在匹配对手与模式”。
- `locking`：对手或模式已经先行选定，依据目标槽位计算角度；轮盘减速并精确落点。
- `reveal`：目标铭牌与指针同时确认，先公布匹配对象。
- `dealing`：从与轮盘独立的真实题库抽题，按钮保持禁用。
- `ready`：题卡出现后，将键盘焦点移到“进入这道题”。
- 动画只改变 `transform` 与 `opacity`，旋转由 MotionValue 驱动，不逐帧写 React state。
- `prefers-reduced-motion` 下省略连续旋转，只保留短暂状态切换并立即落点。

## 自检与修订

- 未使用紫色、蓝紫渐变、玻璃拟态或大面积发光，因此不属于通用 AI 产品页模板。
- 没有用一组同尺寸大圆角卡片堆满页面；信息层级由控制台、轮盘、揭晓区三个功能区域承担。
- 初稿曾考虑暗色魔法大厅，但它会把主题推向通用奇幻游戏，也会脱离现有站点。现改为浅色精密仪表：用 Trace、Checkpoint、Runtime 状态等真实 Agent 工程概念建立识别度。
- 强动效只花在一次完整的“搜索—锁定—揭晓”编排上，其他装饰保持安静。
- 原创视觉只借用卡牌游戏的悬念与揭晓节奏，不复刻炉石的商标、卡背、边框或界面资产。
