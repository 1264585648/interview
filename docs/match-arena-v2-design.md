# Match Arena V2：全屏游戏场景设计

## 主题、受众与单一任务

- 主题：AI Agent 工程师的“星铸试炼场”。它是一局可操作的卡牌匹配，而不是题库的仪表盘皮肤。
- 受众：希望用短局、对手人格和挑战规则练习面试回答的 Agent 工程师。
- 单一任务：点击轮心召唤试炼，先匹配对手或模式，再接住牌库发出的真实题目并进入作答。

## 游戏色 token

Match Arena 使用页面私有的游戏色，不继承现有浅色站点 token：

| 角色 | Token | Hex | 用途 |
| --- | --- | --- | --- |
| 深空黑 | `--arena-void` | `#050914` | 场景遮罩、最深背景、卡牌文字 |
| 星盘蓝 | `--arena-table` | `#0A1827` | 牌桌、铭牌内层、题卡深色面 |
| 符文青 | `--arena-rune` | `#42D9F5` | 法阵能量、进行中状态、焦点 |
| 旧金 | `--arena-gold` | `#C89B52` | 轮盘边缘、对手印记、卡牌框 |
| 羊皮纸 | `--arena-parchment` | `#E8D5A9` | 正文、题卡内容面、主要可读文字 |
| 余烬橙 | `--arena-ember` | `#F08B45` | 命中爆发、关键规则、锁定反馈 |

## 字体角色

- 显示字体：`STKaiti / KaiTi / Noto Serif SC / Songti SC`。仅用于“星铸试炼”、对手名与题卡标题，让铭刻感来自中文笔形而不是装饰英文。
- 正文字体：`Noto Sans SC / PingFang SC / Microsoft YaHei`。用于题目、说明和真实操作文案。
- 工具字体：`Bahnschrift / DIN Alternate / Consolas`。用于阶段、牌库数量、对手/模式类型；这些文字只传递真实游戏状态。

## Signature：召唤轴与击发式发牌

唯一记忆点是一条可见的“召唤轴”：轮盘锁定后，对手或模式印记从顶部席位压入轮心，引发 Canvas 余烬粒子爆发；随后底部牌库把一张卡背沿弧线击发到中央，卡牌到位后翻面显示真实问题。这条因果链把匹配结果与题库抽题明确拆开，也让动效承担规则说明。

## 状态与动效

`idle → searching → locking → reveal → dealing → ready`

- `idle`：轮心可点击，牌桌只保留低频能量呼吸。
- `searching`：WebP 盘体和 HTML 铭牌作为同一转子匀速旋转；音效开启时播放轻微 tick。
- `locking`：已先选定目标 profile，再根据槽位计算落点；使用 MotionValue 减速，不逐帧更新 React state。
- `reveal`：目标印记从对手席压入轮心，Canvas 粒子只负责这一次爆发。
- `dealing`：独立抽取的题目卡背从底部牌库沿曲线飞到中央。
- `ready`：卡牌沿 Y 轴翻面，显示真实题目与“进入这道题”。
- `prefers-reduced-motion` 下直接落点，取消连续旋转、粒子和长距离飞行，只保留阶段文字与即时翻面。

## 自检：为什么它不是后台

- 没有复用 SiteHeader、浅色页面容器、左右栏、控制台、数据面板、`dl` 读数或表格。
- 页面打开后首先看到的是可操作轮盘，而不是标题介绍或指标。
- 题库数量依附在实体牌库旁，对手类型依附在印记和槽位上；状态信息都在游戏对象附近，不单独装进矩形卡片。
- 主要结构是上下席位与中央法阵，符合牌桌空间关系；不会替换文案后变成 SaaS dashboard。
- 原创概念图只作为暗化氛围层，所有文字、按钮和最终落点仍由真实 DOM 控制。
- 没有用紫色霓虹、玻璃卡片或通用游戏 HUD 堆叠；青色代表法阵能量，旧金代表物理器物，余烬只用于命中瞬间。
