# 匹配转轮验收标准

## 交互

- 转轮包含 `idle`、`searching`、`locking`、`reveal` 四个阶段。
- 转轮只匹配对手或挑战模式，不在槽位中显示题目标题。
- 匹配逻辑先确定目标对手/模式，动画再按其索引计算最终落点。
- 搜索阶段匀速旋转，锁定阶段有清晰减速和命中反馈。
- 匹配过程中禁止重复触发；完成后可重新匹配。
- 锁定对手/模式后，题目从独立牌库发出为卡片；卡片能够进入对应题目详情页。

## 视觉与 AI 资产

- 视觉为原创奇幻卡牌游戏风格，不复制现有游戏的商标、角色或原画。
- 中文标题、题目和按钮均由 HTML 渲染，生成图片不承载关键文字。
- ChatGPT Images 2.0 至少交付一张 16:9 概念图、一张卡背和一张轮盘装饰资产。
- Gemini Canvas 至少交付一个可运行、可检查源码的转轮动效参考。
- 采用的生成图片无水印、无乱码文字，并保存到项目目录。

## 工程与性能

- 在现有 Next.js 项目提供一个可访问的演示页面。
- 主体使用 DOM、CSS、SVG 与 Motion；Canvas 只用于粒子或光效。
- 旋转过程不逐帧调用 React `setState`，主体动画仅改变 `transform` 和 `opacity`。
- 不使用预渲染视频代替实时匹配。
- `prefers-reduced-motion` 下跳过长时间旋转并保留清晰状态变化。

## 可用性与完成判定

- 开始按钮可用键盘操作，状态变化通过 `aria-live` 表达。
- 页面在 320px、768px 和 1440px 宽度下无横向溢出。
- `npm run build` 通过，浏览器控制台无明显运行错误。
- 在浏览器中连续完成至少三轮匹配，落点与揭晓的对手/模式一致，题目随后从独立牌库发出。
